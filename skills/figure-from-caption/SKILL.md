# 从图注描述生成图

`knowledge-doc-writing` skill 写文章时会留下「图注描述：……」这样的占位段落，描述应该画什么图。这个 skill 负责把这些描述真的画出来——生成 SVG 矢量图，再可选地转成 PNG 给飞书、微信等平台用。

## 何时触发这个 skill

- 用户文档里有 `图注描述：……` 这样的纯文本占位段
- 用户明确说「把图生成一下」「按图注画图」「这些图导出来」
- 用户说「转成 PNG」「放到飞书/微信」并附带 SVG 文件
- 用户需要为技术文章/教程配示意图、对比图、流程图

如果用户只是想要一两张随手画的图、或者图非常简单（一根箭头、一个矩形），可以直接内嵌 SVG 或用 ASCII，不必动用整个工作流。

## 工作流程

### 第 1 步：扫一遍 markdown，收集所有占位符

读用户给的 markdown 文件，找出每一处 `图注描述：……` 段落（可能是单行，也可能是多行连续描述）。每一处对应一张要画的图。

收集时记下：
- 它在文件的哪一节（用来给文件命名，如 `01-everything-is-box.svg`）
- 描述里的关键视觉元素（盒子位置、颜色、箭头方向、文字标签）
- 这张图想传达的核心对比或流程（图注描述末尾通常会有「核心想传达：……」）

### 第 2 步：决定输出目录

默认放在 `<markdown所在目录>/images/<chapter-id>/` 下，例如 `Notes/css-tutorial/images/ch03/`。如果用户没指定，按这个约定来；如果约定和用户已有的目录结构冲突，问一下。

PNG 放在 `images/<chapter-id>/png/` 子目录，避免和 SVG 混在一起。

### 第 3 步：为每一张图写 SVG

按照下面的「SVG 设计规范」一节的约定，逐张写 SVG。先写一张让用户看效果，再继续——风格统一比一次性堆完更重要。

如果同一份文档有多张图，**保证视觉风格一致**：相同的字体栈、相同的色板、相同的 viewBox 比例、相同的标注引线风格。读者一路读下来，图风格跳来跳去会很出戏。

### 第 4 步：把图引用写回 markdown

每写完一张 SVG，立刻用 Edit 把对应的「图注描述：……」段落替换成 markdown 图片引用：

```
![简短的图说](images/ch03/01-everything-is-box.svg)
```

alt 文本要简短具体，不要复述整个图注描述。

### 第 5 步：批量转 PNG（按需）

如果用户提到飞书、微信、Notion、要导出、要上传等，运行 `scripts/svg-to-png.sh`。脚本默认用 `rsvg-convert` 转 1440px 宽的 PNG，并且加上 `#f8f9fb` 的偏冷浅灰背景（比纯白更耐看，避免在白色聊天界面里"消失")。

```bash
bash <skill-path>/scripts/svg-to-png.sh <svg-dir> [width] [bg-color]
```

如果 `rsvg-convert` 没装，提示用户：

```bash
brew install librsvg
```

不要回退到 `qlmanage`——它强制 1600×1600 正方形，四周留大片白边，效果远不如 `rsvg-convert`。

## SVG 设计规范

下面这套约定是从实战里总结的，照着写图风格统一、Chinese 字体不会变方块、PNG 里文字也锐利。

### 画布与字体

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 760 460"
     font-family="-apple-system, 'PingFang SC', sans-serif">
```

- **用 `viewBox` 而不是 `width`/`height`**，让图能等比缩放
- 横向图常用比例：`760×400` ~ `760×500`（A4 横向友好）
- 字体栈固定写 `-apple-system, 'PingFang SC', sans-serif`，中英文都好看
- 代码段单独用 `font-family="ui-monospace, 'SF Mono', monospace"`

### 色板

固定使用以下 6 组色（浅色填充 + 深色描边/文字），保持视觉一致：

| 用途 | 填充 | 描边/标签 | 文字 |
| --- | --- | --- | --- |
| 蓝（content / 主体） | `#dbeafe` / `#bfdbfe` | `#3b82f6` | `#1e3a8a` / `#1e40af` |
| 绿（padding / 成功） | `#dcfce7` / `#bbf7d0` | `#22c55e` | `#14532d` |
| 黄（border / 警示） | `#fef3c7` / `#fde68a` | `#d97706` / `#f59e0b` | `#92400e` / `#78350f` |
| 橙（margin / 强调） | `#fed7aa` | `#fb923c` / `#f97316` | `#9a3412` |
| 红（错误 / 溢出） | `#fee2e2` | `#ef4444` / `#fca5a5` | `#991b1b` / `#dc2626` |
| 紫（公式 / 总结） | `#faf5ff` | `#c4b5fd` | `#6d28d9` / `#7c3aed` |

灰阶用 `#f8f9fb`（背景偏色）/ `#e5e7eb`（分割线）/ `#94a3b8` ~ `#666`（次要文字）/ `#0f172a`（代码块底色）。

### 嵌入代码块的样式

文章配图里经常要展示一段 CSS / HTML / 命令行。统一用以下样式：

```svg
<rect x="..." y="..." width="280" height="..." fill="#0f172a" rx="6"/>
<g font-size="13" fill="#e2e8f0" font-family="ui-monospace, 'SF Mono', monospace">
  <text x="..." y="..."><tspan fill="#7dd3fc">key</tspan>: <tspan fill="#fbbf24">value</tspan>;</text>
</g>
```

颜色对应：属性名/标签名 `#7dd3fc`（青）、值/字符串 `#fbbf24`（金）、注释 `#94a3b8`（灰）、关键字 `#fb7185`（粉红）。

**代码块要拆成多行写**——不要为了节省空间把整段挤成一行，文字会溢出代码块的右边界。每行控制在 30 个英文字符以内，中文 12 个字以内。

### 箭头与标尺

箭头用 `<defs>` 里定义的 marker 复用，不要每个箭头都重新画三角形：

```svg
<defs>
  <marker id="arrow" viewBox="0 0 10 10" refX="9" refY="5"
          markerWidth="6" markerHeight="6" orient="auto">
    <path d="M0,0 L10,5 L0,10 z" fill="#666"/>
  </marker>
</defs>

<line x1="..." y1="..." x2="..." y2="..." stroke="#666" stroke-width="1.5"
      marker-end="url(#arrow)"/>
```

标尺（双向箭头表示尺寸）两头都用 `refX="5"` 的居中 marker，并同时设置 `marker-start` 和 `marker-end`。

### 抽象边界用虚线

实物边界（一个真实的盒子、一段代码、一个浏览器窗口）用实线；抽象/逻辑边界（content 区、padding 区、可视化的"想象中"对比）用 `stroke-dasharray="4 3"` 或 `"3 3"` 的虚线。让读者一眼就能区分"这是真实的 vs 这是示意的"。

### 标签与引线

- 直接贴在元素上的标签：`font-size="10"` ~ `"11"`，颜色和元素描边色同系（深一档）
- 元素旁边的解释标签用引线连过去：`<line>` + 末端 marker，标签字号 `12` ~ `13`
- 大标题：`font-size="14"` ~ `"16"`，`font-weight="600"` 或 `"700"`
- 副标题/说明：`font-size="11"` ~ `"12"`，`fill="#666"`

## 转 PNG 的细节

- **背景偏色**：`-b "#f8f9fb"`，比纯白更不刺眼，在飞书/微信白色界面里也有边界感
- **宽度**：`-w 1440` 是默认的"平台友好尺寸"，文件 ~ 100 KB，飞书内显示锐利
  - 需要更高分辨率（比如打印）：`-w 2560`
  - 缩略图：`-w 800`
- **不要在 SVG 里硬编码白色背景**——保持 SVG 透明，背景由转换工具控制，方便后续换主题

`scripts/svg-to-png.sh` 已经把这些都封装好了，正常情况直接用即可。

## 常见误区

- **不要用 ASCII art 替代 SVG**。文档里画 ASCII 流程图，看着像图但读起来要"翻译"，零基础读者会卡壳。
- **不要在描述模糊时硬画**。如果图注描述只说"画一个对比图"但没说怎么对比，回头问用户，不要凭感觉乱画一张让人产生错误心智模型的图。
- **不要给一张图加太多元素**。一张图传达一件事：要么是布局对比，要么是流程，要么是状态变化。要传达 3 件事就拆成 3 张图。
- **配色不要超过 3-4 个主色**。每多一种颜色，读者就要多记一个"这种颜色代表什么"的映射，超过 4 种就开始反作用。

## 输出汇报

全部图生成完后，给用户一张表说明成果：

| # | 图位 | SVG | PNG | 内容 |
| --- | --- | --- | --- | --- |
| 1 | §1 一切皆盒子 | `01-...svg` | `01-....png` | 一句话内容描述 |

如果有占位符没处理（比如用户原本说"我自己画这张"的），明确告诉用户哪几张没动。
